# 同步服务运维

## 必需服务

- PostgreSQL 16+
- S3 兼容对象存储（生产）或持久化本地卷（单机开发）
- TLS 终止代理/负载均衡器

服务本身无会话状态，可运行多个副本。幂等 operation 表和文档行锁均在 PostgreSQL，
对象使用内容哈希命名，因此任意副本都可以处理重试。

## 健康检查

- `GET /health/live`：进程存活。
- `GET /health/ready`：PostgreSQL 可查询。

生产探针应以 ready 作为流量准入，以 live 作为重启依据。

入口代理还必须按来源 IP 对 `/v1/auth/*` 做速率限制。服务自身提供每账户 8 次/分钟的
第二层限制，但多副本部署时边缘层仍是抵御分布式尝试的必要组成。

## 备份

- PostgreSQL：每日全量 + 持续 WAL 归档，至少保留 30 天。
- 对象存储：开启版本控制和生命周期策略，禁止立即永久删除。
- 每季度执行一次异地恢复演练，并验证文档 JSON 能通过当前 `branchly-core`。

## 环境变量

参考 `services/sync-server/.env.example`。`JWT_SECRET` 至少 32 个随机字节；生产环境
`OBJECT_STORE=s3`，且 `AWS_ENDPOINT` 必须使用 HTTPS。

## 资源清理

客户端删除图片不会立即删除云对象。服务端应以“所有文档资源清单均不再引用且超过
30 天”为条件执行后台清理，避免离线设备或冲突副本恢复时出现资源缺失。
